# v8.7 恢复 `event_type` 描述性 + 消除「两个事故等级」

日期：2026-10-09 ｜ **未 commit** ｜ 承接 v8.6（场景受控归类）

原始输出：`_test_v8_7_raw.txt`（4 例）｜ 输入：`_v8_6_input.txt`

---

## 一、起因：v8.6 的两个尾巴

### 尾巴 1｜副作用：`event_type` 被带向词表

v8.6 在 prompt 里给的 4 个映射示例，让模型"顺带"把 `event_type` 也对齐成了词表键
（case_047：`高架桥下仓库起火波及线路声屏障` → `站外失火`），**损失描述性**。

### 尾巴 2｜一个既有的、更深的矛盾（本轮才看清全貌）

同一个"事故等级"，系统里有**两套互斥规则**，而且**同一条 prompt 里就打架**：

```
【事件画像】                                 ← generate_plan 的 prompt 里
- 事故等级：{severity}        ← 来自 event_understand 的**推断值**（规则2："没有明确数据就按可能后果推断"）
- 等级依据：{severity_reason}

【硬性约束（一）】                            ← 同一条 prompt 里
信息不足时，severity.level 必须原样写"信息不足…"
**禁止**使用"按可能后果推断"…等表述来定级
```

**模型选了约束** → 10/10 真实案例的方案都写"信息不足"，`event_understand` 的推断成了**死信息**；
而 `main.py` 仍在**另外打印**那个推断值 → **用户在同一屏看到两个互相矛盾的"事故等级"**。

> **这正是用户最初那句"只有给到精确数字才能定级"的根因**——推断其实一直在做，只是从来没进到方案里、也没人认它。

---

## 二、改动

### ① 恢复 `event_type` 描述性（`event_understand.py` prompt）

- schema 注释明确：`"event_type": "**照实描述本次事件**…不要套用场景词表里的键"`
- 场景词表块补一句：**`event_type` 照实描述、可自由用词；`scene_key` 必须原样用键；两者不要互相替代**，
  也不要为了对齐 key 而把 `event_type` 写笼统。

### ② 把推断**接进初判**，消除双值

| 位置 | 改动 |
|---|---|
| `plan_generator.py`【事件画像】 | `- 事故等级：{severity}` → **`- 解析器初步印象（仅供参考，不是定级依据）：{severity}｜依据：{severity_reason}`** |
| `plan_generator.py` 约束（一·补） | 补一条：该「初步印象」**可采纳也可否决**，但**必须写出自己的依据**；**不得直接抄成 `severity.level`** |
| `main.py` 打印 | `事故等级：…` → **`事故等级（解析器初步印象，仅供参考）：…`** |

**方向选择说明**：在"接进初判"与"删掉 event_understand 那套"之间，选前者——**保留信息、不删能力**，
但把它**降级为参考**（标注口径 + 不得直抄），让 `preliminary`（带置信度与依据）成为**唯一的定性初判出口**。

## 三、验证（4 例实跑）

| case | ① `event_type`（应恢复描述性） | `scene_key` 检索用（应仍是受控键） | ② 方案正文 |
|---|---|---|---|
| case_047 | **高架桥下仓库起火波及线路声屏障** ✅ | `站外失火` ✅ | 事故等级=信息不足；**初判=一般（置信：中）** + 依据 |
| case_075 | **地铁隧道内边墙明火** ✅ | `隧道火灾` ✅ | 事故等级=信息不足；**初判=一般（置信：中）** + 依据 |
| case_081 | **车站发现疑似爆炸物品（防爆演练）** ✅ | `恐吓事件` ✅ | 事故等级=信息不足；**初判=一般（置信：中）** + 依据 |
| case_085 | **乘客突发心脏骤停** ✅ | `乘客突发疾病` ✅ | 事故等级=信息不足；**初判=一般（置信：中）** + 依据 |

**① 完全达成**：`event_type` 描述性回来了，`scene_key` 仍是受控键——**两者各司其职**。

**② 双值消除**：`main.py` 打印已标注口径，方案正文用「事故等级（合规）+ 初判等级（带依据）」两轨——**不再互相矛盾**。

**初判准确性累计**：case_003 ✅ / case_075 ✅ / case_081 ✅ / case_085 ✅ / **case_047 ❌（判为"一般"，案例标注"较大"）** = **4/5**。
