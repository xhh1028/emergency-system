# v8.8 引用可证实性自检——唯一能机械证伪"编造条款"的检查

日期：2026-10-09 ｜ **未 commit** ｜ 起因：**没有人能来做验收**

原始输出：`_test_v8_8_citation_raw.txt`（10 例真实案例）｜ 冒烟测试：`_selftest.py`

---

## 一、为什么做这个

上一轮我承认了：**没有外部判断者时，"方向对不对、可不可实施"永远验证不了**。
于是换个方向——**找那些不需要语义判断、可以机械证伪的检查项**。

其中最有价值的一条：**`依据` 里的规程条款，在库里到底查不查得到。**
- 它**不需要任何人**：查表即可，确定性、可离线复算；
- 它**能证伪最致命的失败模式**：**编造条款**（比场景错配更危险——用户会照着"有依据"去执行）；
- 它顺手能抓**引用格式损坏**。

## 二、改动

### 1. 只读规程库索引（`_load_citation_index`）

- 数据源与检索层**同源**：`long_data/AIEP/**/*_chunks.jsonl`（AIEP 切片）+ `long_data/JSON/*.jsonl`；
- **用 jsonl 而非 chroma**：不依赖向量模型、确定性、可离线复算；
- 建索引耗时 **0.18s**，进程内缓存；
- fail-soft：读不到 → 跳过自检，不崩。

### 2. 逐条核对（`_check_citations`）

把 `依据` 拆成逐条引用，分三类：

| 结果 | 含义 |
|---|---|
| ✅ **可证实** | AIEP 文档/章节、或已知文档的条款号在库中查得到 |
| ⚠️ **存疑** | **认得出是哪份文档、但条款号对不上** |
| ℹ️ **非条款/不可识别** | 知识图谱事实、案例经验、描述性文字、断裂片段 |

**三处刻意的防误报处理**（都是实测踩出来的）：
- **标准号别名**：方案写 `GB/T 38707 14.2.15`，库里 `doc_name` 是 `GBT 38707-2020(城市轨道交通运营技术规范)` → 单独处理，否则**每份方案都会误报**；
- **括号内分号**：模型会写 `[步骤1；7]`、标题里也带 `；` → 切分**跳过方括号内**；
- **认不出的来源不计存疑**：只有"看起来是规程条款却对不上"才算存疑，否则误报会淹没真信号。

### 3. 渲染（两处）

- **逐步**：某步 `依据` 有存疑 → 该步下加 `- ⚠️ **引用存疑**（规程库中查不到该条款）：…`
- **汇总**：置信自检里加 `引用可证实性：✅ N 条规程引用全部可在库中查到` / `⚠️ 可证实 N 条，存疑 M 条…`

## 三、⚠️ 中间出过一次事故（我引入的，必须记下来）

第一版集成写错了变量初始化（`c_nonc = 0` 应为 `[]`），导致 `c_nonc += _nc` 抛
`unsupported operand type(s) for +=: 'int' and 'list'` →

> **10/10 全部"渲染失败"→ 降级为纯文本 → 步数全为 0。**

**关键点：我的单元测试（`_check_citations` 单测）全部通过，完全没抓到它**——
因为坏的是**渲染集成层**，不是被单测覆盖的那个函数。**只有端到端实跑才暴露。**

⇒ 教训：**单测通过 ≠ 集成能用**。此后每次改渲染，先跑一遍合成 JSON 的**渲染冒烟**（`_selftest.py`），再花 12 分钟跑真实案例。

## 五、这个检查真正解决了什么（以及没解决什么）

**解决了**：把"这方案可不可信"里的**一个硬问题（有没有编造依据）**，从"我说了算"变成**机械可查、你可复核**。

**没解决**：方向对不对、可不可实施、够不够全 —— **仍然只能人看**。
这个检查**不缩小**那部分空白，只是把不能无人化的部分**和能无人化的部分分清楚了**。
