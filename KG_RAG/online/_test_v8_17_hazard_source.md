## 一、改动

### 改动 1｜prompt 新增（十五）危险源处理原则（标题 `十四条` → `十五条`）

> 若事件涉及**持续危险源**，必须安排**至少一个"处理危险源"的独立步骤**，排在阶段一或阶段二：
> 火灾/爆炸 → 灭火扑救/消防喷淋/隔离可燃物；持械袭击 → 控制/隔离行凶者；有毒气体泄漏 → 隔离气体源/关阀门；
> 带电设备 → 隔离电源；相撞/脱轨 → 阻止后续列车进入。
> **禁止只处理后果（疏散/救治/报告/排烟），不处理危险源本身。**
> 不存在持续危险源的场景（如"乘客突发疾病"）**不适用**。

### 改动 2｜词表 + 告警（`_check_hazard`，**不上硬顺序**）

```python
KW_FIRE   = 灭火|扑救|消防喷淋|消防设施|使用灭火器
KW_ATTACK = 控制/隔离/封锁.{0,4}行凶 | 制止.{0,4}袭击 | 反恐响应
KW_GAS    = 隔离.{0,4}气体源 | 关闭.{0,4}阀门 | 切断.{0,4}气源
```
按**事件画像**判断场景属于火灾/袭击/气体 → 查方案里有无步骤命中对应词表 → 无则 `[hazard] WARNING …`。

**不上硬顺序**：先看 LLM 能否在（十五）约束下自主补出；**补不出再上硬约束**。

## 二、观察结果：**LLM 自主补出 2/3**

| 用例 | 结果 |
|---|---|
| ① 某地铁站台发生火灾，火势蔓延，需紧急疏散乘客。 | ✅ **已安排「灭火 / 扑救」——步骤 1**（第 1 步就是灭火，很靠前） |
| ② 某车站站厅内发生持刀伤人事件，三名乘客受伤，行凶者仍在现场。 | ✅ **已安排「控制 / 隔离行凶者」——步骤 3** |
| ③ 某车站内出现不明气体泄漏，多名乘客出现中毒症状。 | ❌ **WARNING：未安排「隔离气体源 / 关阀门」** |

### 用例③ 是**真阳性**：它处理了"扩散"，没处理"源"

方案前 6 步：

```
1 [信息报告] 找出不明气体的位置、来源、颜色、气味…立即向值班站长报告   ← 只是"找出"，不是"隔离"
2 [信息报告] 通知行车调度员…
3 [切断危险源] 与行车调度员查证没有列车准备驶经有关车站，并确认**已关掉车站的通风系统**  ← 防扩散
4 [人身安全] 召唤救护车，对中毒乘客现场施救
5/6 [人身安全] 疏散车站…
```

**关通风 ≠ 关气源**。全篇**没有一步**去隔离气体源 / 关闭相关阀门——**危险源还在持续产出**。

⇒ 按你的框架：**火灾、袭击 LLM 能自主补出；气体泄漏这一类不能** → **这一类才需要上硬约束**。

## 三、修检查器时发现并修掉的一处缺陷

首跑时**用例③额外报了一条"火灾/爆炸场景未安排灭火"**——查下来是我的 `blob` 用了 `str(整个 event_profile)`：

```
event_profile 里有："scene_key": ["站内失火"]     ← 「不明气体泄漏」被受控归类成「失火」！
```

触发词里的 `失火` 命中的是**归类结果**，不是事件描述 → **误触发**。
已改为 blob **只取事件描述类字段**（事件类型 / 次生事件 / `key_facts` / 位置），**排除 `scene_key`**。改后用例③ 只剩气体那一条真告警 ✓。

## 四、顺带发现（新，未修）

**受控归类把「不明气体泄漏」归成了 `站内失火`** —— 因为 35 个场景键里**没有"气体泄漏 / 不明气体"这一键**，模型只能挑最像的（火警类）。
后果：检索被引向**火警章节**，而不是气体处置内容。
**修法**：给 `scene_chapter_map.json` 补一个气体类场景键（或把触发词并入 `区间烟雾报警`）。**本轮未动，仅报备。**
