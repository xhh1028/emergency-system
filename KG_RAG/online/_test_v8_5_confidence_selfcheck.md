## 一、为什么做这个

上一轮评估里我把**最危险**的一条列为「**看起来对**」：case_047 把"高架桥下仓库火灾"当成"车站房间火警"处置，
输出**格式完美、依据齐全、步骤完整**——**用户看不出来**。崩溃可以重跑，静默替换场景会被照着执行。

对策不是再补一条规则，而是**让系统自己说出哪里没底**（对应 `_baseline.md` §十二 失败模式 5，P1→本轮按 P0 处理）。

## 二、改动（3 件，全部由**代码判定**，不由 LLM 自述）

| # | 内容 | 触发条件 |
|---|---|---|
| 1 | **顶部声明**：`> ⚠️ 本方案为自动生成的初判草案，须经现场负责人复核后方可执行。` | **恒定**，每份方案都有 |
| 2 | **场景匹配自检**：`场景匹配：✅ 事件类型对上了场景键 ['列车脱轨']` / `⚠️ 未对上任何场景键——检索层将走关键词兜底，引用条款可能不贴切；请重点核对每步「依据」是否真对应本次事件` | 前者命中场景键；后者**未命中** |
| 3 | **复合险情 + 定级自检**：`复合险情：✅ 已识别 N 类` / `⚠️ 未识别…若实际存在多险叠加，本清单可能不全`；`定级：⚠️ 未定级（缺量化要素）——请以「初判等级」为参考，并**以现场核实为准**` | 按 `composite` / `severity.level` 的实际取值 |

### case_047（**原"静默场景错配"那一例**）

```
> ⚠️ 本方案为自动生成的初判草案，须经现场负责人复核后方可执行。
- **事故等级**：信息不足，暂按一般事件处置，持续跟踪升级

  - 依据：描述确认无人伤亡，无直接经济损失和中断行车时间数据，仅提及相关区段运营中断
- **复合情形**：本事件同时包含 **5 类险情**（仓库火灾 / 波及声屏障 / 运营中断 / 桥体受热损伤 / 违建隐患）
```

## 五、⚠️ 一处必须如实说的初判偏差

**case_047：系统初判「一般」，而案例库标注的是「较大事故」——不一致。**

- 系统的依据站得住：描述里明写"**确认无人伤亡**""相关运营受影响 **2 个多小时**"——按 7.2，无伤亡 + 中断 2h 确实落"一般"。
- 案例库标"较大"，更可能来自**结构风险**（高架桥体受热损伤）这类描述里未量化的因素。

**⇒ 初判累计：case_003 ✅ / case_075 ✅ / case_047 ❌ = 2/3。**

这恰好印证：**初判是参考，不是结论**——它只依据"描述里已经写出来的事实"，描述没写的（桥体风险）它就看不见。
这正是本轮为什么要把它标成 `（置信：中）` + 顶部挂"须人工复核"——**不是为了免责，是因为它真的会错**。
