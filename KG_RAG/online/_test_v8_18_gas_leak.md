## 一、步骤 1｜加场景键 —— **两处偏差，如实说明**

你给的键是 `"气体泄漏": {"aliases": [...], "pins": []}`。但查下来：

**偏差 ①：`aliases` 字段不存在**
现有 **35 个键全是 `allowed`/`forbidden`/`pins`**，**没有一个用 `aliases`**（0/35）。加了也没代码读 → **死配置**。
它也不是匹配用的——匹配（`_match_scenes`）是拿**键名**与事件类型做子串；而当前一线机制是**受控归类**（LLM 从 `_load_scene_keys()` 动态列出的键里选）。

**偏差 ②：光改 `scene_chapter_map.json` 不会让"材料变成气体类章节"**
系统有**两张**场景表：

| 表 | 位置 | 作用 |
|---|---|---|
| `scene_chapter_map.json` | 数据文件 | `allowed`/`forbidden` → **场景过滤** |
| `SCENE_TO_CHAPTERS` | **`main.py`（Python dict）** | **强制拉入**关键章节 |

**拉哪些章节来自 main.py 那张表**，JSON 里加键做不到。而没有 `allowed` 的键，过滤层直接跳过。

**所以实际改了两处**（都属"补字典、不改算法"，符合"封版封的是算法不是字典"）：

```jsonc
// scene_chapter_map.json —— 与现有键同格式
"气体泄漏": {
  "allowed": ["AIEP08_8C3", "AIEP08_8C4", "AIEP08_8C1", "AIEP08_8C2",
              "AIEP11_11A", "AIEP12_12B", "AIEP03_3A"],
  "forbidden": ["AIEP15", "AIEP10"],
  "pins": []
},
```
```python
# main.py 的 SCENE_TO_CHAPTERS
"气体泄漏": ["AIEP08_8C3", "AIEP08_8C4", "AIEP08_8C1", "AIEP08_8C2",
             "AIEP11_11A", "AIEP12_12B"],
```

章节选择依据（**实测语料统计**）：`AIEP08 8C3 处理车站内的不明气体/物体`（25 条，主章节）、`8C4 处理列车上的不明气体/物体`（11 条）、`8C1/8C2`（袭击处置/OCC）、`AIEP11_11A`（紧急通风）、`AIEP12_12B`（疏散）。

## 三、步骤 3｜气体类硬约束 ✅ 3/3 补入

新增 `_inject_hazard_step(seq, event_profile, front_n, log)`：

- **只对 `scene_key` 含"气体泄漏"生效**；
- 若方案已有步骤命中 `KW_GAS` → 不补；
- 否则**补入一条预定义安全底线步骤**，插在**占位槽位之后**（`front_n`，保证靠前又**不挤掉挡水/救治/疏散的槽位**）。

### 补入的步骤（RUN1 原文，渲染后为**步骤 2**，落**阶段一**）

```
**步骤2**：值班站长安排车站员工在确认安全的前提下关闭相关区域通风系统、切断可能的气源
          （关闭相关阀门），并在安全位置持续监测气体浓度
- 阶段/时限：先期处置 · 目标 3 分钟内完成
- 优先级：切断危险源
- 岗位：值班站长、车站员工
- 依据：（系统补入：危险源处置安全底线动作，非本次检索到的规程条款）
```

**依据明标为「系统补入」** —— 本系统的原则是"不编造"，但"危险源不除、后果会持续产生"不能只告警了事；
所以补一条**预定义的安全底线**，并**如实标注它来自系统、不是本次检索到的条款**（不冒充规程依据）。

### 火灾 / 袭击 **不误补**（它们 LLM 已能自主补出）

| 用例 | `[hazard]` 日志 |
|---|---|
| 站台火灾 | `✅ 已安排「灭火 / 扑救」——步骤 5`（无补入） |
| 持刀伤人 | `✅ 已安排「控制 / 隔离行凶者」——步骤 3、4、9`（无补入） |
| 气体泄漏 | `**缺处理气体源的动作** → 已于第 2 位补入安全底线步骤` |
