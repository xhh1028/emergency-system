## 三、暴雨疏散 4/5 —— 如实报告（**不是本次修复的词序缺口**）

**未达标：期望 5/5，实测 4/5。** 但剩下的这一漏，**与本次新增的正向序模式无关**，是另一种失败形态：

**暴雨 RUN2 失败样本**（`[rule] WARNING 疏散 全文无…`），该次全部第 1 档步骤：
```
步骤1 [切断危险源] 指派员工携带防洪板、沙包在受影响出入口实施挡水，防止雨水继续倒灌
步骤2 [人身安全]  指派员工前往站台拥挤区域引导乘客疏散，优先救助摔倒老人   ← 复合动作
步骤3 [切断危险源] 开启出入口排水设施进行排水，对无排水设施的出入口采用手提潜水泵排水
步骤4 [人身安全]  立即召唤救护车并将摔倒老人送医救治
步骤5 [切断危险源] 前往水淹现场视察，评估出入口、楼梯口积水情况及设备房进水情况
```

**根因 = 复合动作 + 规则求值顺序**：

- 步骤2 是一个**把两个动作塞进同一 `action`** 的复合步（`引导乘客疏散` + `优先救助摔倒老人`）——
  **违反 prompt 硬性约束（九）每步单一动作原则**，属 **prompt 层**问题；
- `POSITION_RULES` 顺序是 **挡水 → 救治 → 疏散**；步骤2 的首句**同时**命中 `KW_JIU`（救助）与 `KW_SHU`（引导…疏散）；
  **救治先求值** → 占走步骤2（槽位2）→ 步骤2 被 `claimed`，疏散再看其余第 1 档步骤，**没有第二个疏散步** → 不占位。

即：该次 LLM 只写了一个复合的"疏散+救治"步，规则把它归给了救治。**`KW_SHU` 并未失配**（该首句本来就命中），本次新增模式也不会改变这个结果。

> **验证新增模式确有其效**（§一单元验证）：本批 5 次里 `…加快疏散速度，并优先引导老人…` 这类**旧表必漏**的写法已被命中。

**结论**：本次修复**达成了它的目标**（补上词序缺口）；暴雨疏散未到 5/5 是**另一个未修问题**（复合动作 / 规则求值顺序），属 prompt 层，需要另开一轮裁定，**本次不越界处理**。

## 四、恐袭 2/3 —— 无回归，失败形态说明

**恐袭 RUN1 失败样本**：该次第 1 档只有 1 个含疏散/撤离的步：
```
步骤4 [人身安全] 为伤残人士、老人、儿童等弱势群体提供或安排协助撤离    ← KW_SHU 不命中
```
- 其余含"疏散"的步（`宣布疏散车站`、`引导乘客…撤离车站` 等）被 LLM 标成 **`运营调整`**，而恐袭用**默认 TIER**（`运营调整`=第 3 档）→ **不是第 1 档候选**，规则按设计不看；
- 唯一第 1 档候选用的是裸「**协助撤离**」——`KW_SHU` 无裸 `撤离` 模式（现有模式都是 `撤离车站`/`引导…撤离`）→ 不命中。

**这不是回归**：本次改动**只新增一个 alternation**，不可能移除任何原有命中；两种成因（LLM 分类、裸"撤离"词形）都在改动之前就存在。
