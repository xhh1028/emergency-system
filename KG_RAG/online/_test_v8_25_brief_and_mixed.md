## 二、实测效果（混合场景）

**输入**：`早高峰暴雨天气列车撞击异物导致信号故障和乘客受伤`


**作战简报（49 行 / 2,280 字）** —— 指挥员速读层：

```
- **⚠️ 耦合风险链推演**：
  1. 暴雨 + 信号故障 → **列车追尾**（降级运行下制动距离延长、区间追踪间隔被压缩）
  2. 早高峰客流 + 乘客受伤 → **大客流踩踏**（伤员处置占用站台空间，客流持续涌入）
  3. 轨面湿滑 + 信号故障 → **二次撞击**（湿滑延长制动距离，信号故障致防护区段失效）
- **⚔️ 处置冲突与协同**：
  - **冲突点**：暴雨防触电要求关闭车门、切断相关电源，但乘客受伤和区间迫停要求打开车门疏散救治
  - **协同策略**：先确认接触轨已隔离、轨面无积水漏电，在防触电前提下手动开门疏散，同步设置挡水板
  - **冲突点**：信号故障要求立即扣停所有列车，但早高峰大客流要求尽快恢复行车
  - **协同策略**：先扣停受影响区段并隔离危险源，确认区间安全后以限速手控模式恢复未受影响区段
- **五、升级触发条件**：重伤≥10人 / 死亡≥3人 / 损失≥1000万 / 中断≥6小时 → III 级；……
```

## 三、本轮真踩到的坑（已加回归守卫）

**`_l()` 用在 dict 列表上 → 整列被静默清空。**

`_l()` 面向字符串列表，内部 `_s(i)` 会把每个元素 `str()` 化：
`[{"event_type":"信号故障"}]` → `["{'event_type': '信号故障'}"]` → 后续 `isinstance(x, dict)` **全 False**。

后果（端到端实跑才暴露）：作战简报里
- 「次生/衍生事件」被误渲染成 **「无」**
- 「升级触发条件」被误渲染成 **「（未给出升级触发条件）」**

而同一份数据的详案层渲染正常 —— **只有简报层错**，是个很隐蔽的分层 bug。

**修法**：新增 `_ld()`（`(v or [])` + `isinstance` 过滤，即代码库 `tiers`/`fallback` 的既有约定），
替换 5 处误用；并在 `_test_v8_25_verify.py` §1 加了直接断言 `_l()` 会破坏 dict 列表的**回归守卫**。
