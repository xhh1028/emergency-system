# 引用存疑排查：校验器**误报**（根因＝正则不认下划线）

**日期**：2026-10-10 ｜ **只查不改**
**触发用例**：`某地铁站有情况，好像有人受伤`（**不在本批归档**，用户实测）
**留档**：本文

---

## 〇、结论（一句话）

**这些引用在库里都存在，不是 LLM 编造。** 「引用存疑」是 **`_check_citations` 的误报**——
它的正则 `AIEP\s*(\d+)\s*([0-9A-Za-z]+)` **不认下划线**，于是把 `AIEP01_1C5` 切成
`AIEP00` + `1`（下划线两侧断开），文档号对不上 → 判"查不到该条款"。

---

## 一、这个标记是谁加的？判据是什么？

**校验器**：`online/plan_generator.py` 的 **`_check_citations(basis)`**（`:312`），
索引由 **`_load_citation_index()`**（`:258`）建立。
**渲染**：`plan_generator.py:1141`

```python
out.append("- ⚠️ **引用存疑**（规程库中查不到该条款）：%s" % "；".join(_sp[:3]))
```

**判据**（`_check_citations` 逐条核对 `basis`，按「；」切分但跳过方括号内 `_split_cites`）：

| 情形 | 归类 |
|---|---|
| 命中 `AIEP\s*(\d+)\s*([0-9A-Za-z]+)` 且 `did=AIEP%02d` **与** `sec` 都在索引里 | 可证实 |
| **同上但文档号或章节对不上** | **存疑 ← 本例** |
| `GB/T 38707 …`（含别名修复） | 单独分支 |
| 认出 doc_name 但条款号对不上 | 存疑 |
| 知识图谱 / 案例经验 / 附录 / 认不出前缀 | 非条款来源（**不计存疑**） |

**索引内容**（`_load_citation_index`，数据源 `long_data/AIEP/**/*_chunks.jsonl`）：
`aiep[doc_id] = { section.split()[0] }` —— **只到"章节首词"这一层**，不含步骤号。
实测索引：

```
AIEP01 → ['1A','1B','1C1','1C2','1C3','1C4','1C5','1C6','目录']
AIEP25 → ['25A','25B','25C','25D','25E','目录']
```

## 三、根因：正则不认下划线（机械证据）

```python
m = re.match(r"AIEP\s*(\d+)\s*([0-9A-Za-z]+)", c)      # plan_generator.py:333
did, sec = "AIEP%02d" % int(m.group(1)), m.group(2).upper()
```

`_` **不在** `[0-9A-Za-z]` 里 → `(\d+)` 回溯成 `"0"`，`([0-9A-Za-z]+)` 再吃下划线后的 `"1"`：

| 输入（真实调用 `_check_citations`） | 正则组 | 结果 |
|---|---|---|
| `AIEP01_1C5 宣布进入运营紧急状态 [步骤1]` | `('0','1')` → `AIEP00`/`1` | **存疑（误报）** |
| `AIEP01_1B 报告事故概述 [规程片段8]` | `('0','1')` | **存疑（误报）** |
| `AIEP01_1C4 值班经理的行动 [规程片段10]` | `('0','1')` | **存疑（误报）** |
| `AIEP25_25C 呈报乘客伤亡 [规程片段17]` | `('2','5')` → `AIEP02`/`5` | **存疑（误报）** |
| **`AIEP01 1C5 …`（空格）** | `('01','1C5')` | **✅ ok** |
| **`AIEP07_7B 清人程序`（归档真实依据行）** | `('0','7')` | **存疑（误报）** |
| `AIEP07 7B 清人程序` | `('07','7B')` | **✅ ok** |

**唯一变量就是分隔符**。换言之：**同一份依据，空格写法通过，下划线写法被误判。**

### 失效方式有**两种**，根因同一个（正则太窄）

| 模式 | 样例 | 正则组 | 后果 |
|---|---|---|---|
| **A · 下划线** | `AIEP01_1C5 宣布进入运营紧急状态` | `('0','1')` | 文档号切错 → 存疑 |
| **B · 章节名是中文** | `AIEP06 安排起复及移动事故列车` | `('0','6')` | 同上 |

**模式 B 的归档实例**：归档中**唯一出现过**的「引用存疑」（`_test_v8_20_full_raw.txt`，2 处）——
被标的正是 `AIEP06 安排起复及移动事故列车`（**空格写法**，但章节名是中文）。
注意：索引里 `AIEP06` 的键**同时含** `6A/6B` 与**整段中文名** `安排起复及移动事故列车`
（`sec.split()[0]` 对无编号章节取整名）→ 只要正则能捕获中文，**这条本可证实**。

**二者同因**：`([0-9A-Za-z]+)` 既不容 `_`、也不含中文；一旦吃不到，`(\d+)` 便**回溯**吃掉文档号首位，
静默变成 `AIEP00`（或 `AIEP02`），于是"查不到"。**这是静默错切，不是真的查不到。**

> ⚠️ **更正（初稿笔误）**：归档中**带下划线的 `依据` 行**（如 `_test_v2_大客流.txt` 的
> `依据：AIEP07_7B [步骤6]`）**并不能**佐证模式 A 曾被标 —— 那些文件**早于 v8.8 引用自检**，
> 通篇 **0 条**「引用存疑」（该功能尚未存在）。故**模式 A 在归档中无实测样本**，
> 其存在性由**本次机械复现**证明（§三表格第 1 行）。

**规模**：`依据` 行里空格写法 ~3000+ 次、下划线写法少数（几十次）→
**误报规模取决于 LLM 当次采样用哪种写法**；触发用例那次恰好大量用下划线，故 11/12 被标。

## 四、"步骤N" 与 "规程片段N" 是**哪来的**？

**都来自 `online/main.py` 的检索上下文格式器**（`search_rag_full` 尾部，`:812–817`）：

```python
source_file = meta.get("source_file", meta.get("doc_name", ""))
source = f"[来源：{source_file} - {meta.get('section','')}]"
step_info = f" [步骤{meta['step']}]" if meta.get("step") else ""
output.append(f"【规程片段{index + 1}】{source}{step_info}\n{doc}")
```

即喂给模型的每段规程长这样：

```
【规程片段8】[来源：AIEP01_1C5_chunks.jsonl - 1C5 宣布进入运营紧急状态] [步骤1]
<正文>
```

- **`规程片段N`** ＝ 该次检索结果里的**序号**（`index + 1`）——**不是**规程条款号；
  模型把它**原样抄进 `依据`**。
- **`[步骤N]`** ＝ chroma 元数据 `meta['step']`（`offline/build_rag.py:92` 写入，`step_of()` 提取），
  指**该章节内的步骤号**，**不是**顶层章节，**不是**方案自身的步骤号。
- **`source_file`** ＝ 切片文件 basename（`build_rag.py:68,88`）→ **`AIEP01_1C5`** ——
  **下划线就是从这里来的**（模型照着上下文里的文件名写）。

**回答"步骤1/步骤9/步骤2 在库里能不能找到"**：库的**章节索引里没有**「步骤1」这一层
（索引只到 `1C5`）；它只存在于 chroma 的 `step` 元数据里。
但因校验器**只判 `AIEP + 章节`**、方括号内不参与匹配，**这不构成存疑原因** ——
存疑**唯一**来自下划线。

### 附带更正

- 你在触发用例里看到的「`规程片段8`」**不是**引用格式，而是**上下文序号被抄进依据**——
  它**不该**出现在 `依据` 里（`依据` 应写规程编号）。这是**另一个（轻微的）问题**：
  **prompt 未禁止把"规程片段N"当引用**。本次仅记录。

## 六、结论

1. **11/12 条"引用存疑"是误报**：引用**全部真实存在**，无编造。
2. **根因**：`plan_generator.py:333` 的 `AIEP\s*(\d+)\s*([0-9A-Za-z]+)` **不认下划线**，
   而模型照抄上下文里的 `source_file`（含下划线）→ 文档号被切错 → 判存疑。
3. **下划线的源头**是 `main.py:814` 把 `source_file`（如 `AIEP01_1C5`）原样喂给模型。
4. **不是新问题**：**模式 B** 在归档中已有实测（`AIEP06 …`）；**模式 A** 由本次机械复现证明。

### 建议（**本次不改**，供裁定）

- **最小修**：放宽正则，同时覆盖 `_` 与中文章节名 ——
  `AIEP\s*(\d+)\s*[_\-]?\s*([0-9A-Za-z一-鿿]+)`
  **实测四种样例全部复原并在库**（对照旧正则）：

  | 引用 | 旧正则 | 新正则 |
  |---|---|---|
  | `AIEP01_1C5 …` | `AIEP00/1` ✗ | **`AIEP01/1C5` ✓** |
  | `AIEP06 安排起复及移动事故列车` | `AIEP00/6` ✗ | **`AIEP06/安排起复及移动事故列车` ✓** |
  | `AIEP07_7B 清人程序` | `AIEP00/7` ✗ | **`AIEP07/7B` ✓** |
  | `AIEP01 1C5 …`（原已通过） | `AIEP01/1C5` ✓ | `AIEP01/1C5` ✓（无回归） |

- 或**在源头统一**：`main.py` 喂上下文时把 `source_file` 规范成 `AIEP01 1C5`（去扩展名、换空格）。
- 附带：prompt 明确「`依据` 只写规程编号，**不得抄『规程片段N』**」。
