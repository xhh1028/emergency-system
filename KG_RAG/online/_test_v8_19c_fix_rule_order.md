## 一、三处改动（对应三条裁定）

| # | 裁定 | 改动 |
|---|---|---|
| ① | **必改**：修 `KW_JIU` 抢认领 | `POSITION_RULES` 把 `召唤外部力量` 提到 `救治` **之前**（槽位号不变，只改认领顺序） |
| ② | 接受 16 步，**加日志** | `_inject_hazard_step` 注入后若 `len(seq) > N_MAX`，记 `[inject] 因注入安全底线步骤…保留（安全动作优先）`（气体/火灾两分支都加） |
| ③ | 顺手修挡水假阳性 | `_flags` 的挡水判据：裸 `积水` → `积水.{0,4}(?:倒灌\|漫\|深\|进入\|上涨\|严重\|涌)` |

```python
# ① 改后
POSITION_RULES = (("挡水", KW_KOU, 3, 1), ("召唤外部力量", KW_CALL, 3, 4),
                  ("救治", KW_JIU, 3, 2), ("疏散", KW_SHU, 5, 3))
```

> **① 的机理**：`_demand_slots` 按 `POSITION_RULES` **顺序**认领。`KW_JIU` 含「救护车\|急救」，
> 会命中召唤句「召唤消防、**救护车**到场」，在旧顺序下（救治在召唤前）**抢先认领召唤步骤**。
> 只改认领顺序、不动槽位号，故 `_order_steps` 的前置位次语义不变；
> 非外部力量场景被 `has_external_need` 门控，**不受影响**。

**改后**每个用例的 `[rule]` 认领（`救治 → 槽位2` 的首句已**不再是召唤句**）：

```

[rule] 召唤外部力量 → 槽位4  首句=值班站长接报后立即通过行车调度员要求消防部门到场处理…

# 案例2  ← v8.19b 里这句是「救治 → 槽位2」，现已被召唤规则正确认领
[rule] 召唤外部力量 → 槽位4  首句=行车调度员召唤消防、公安及救护车到场，并通知值班经理…
# 案例3  ← 同上
[rule] 召唤外部力量 → 槽位4  首句=召唤消防部门到场灭火，并视需要召唤公安及救护车到场协…

```

对照 v8.19b：案例 2/3 当时的日志是 `救治 → 槽位2`（首句为召唤句）+ `WARNING 召唤外部力量 …不占位`。
**改后：召唤规则认领（案例 1/2/3/5），真救治步骤归救治规则（案例 4）。**

### ② 验证：注入超 N_MAX 的日志 —— **通过**

案例 2（步数 16）：

```
[inject] 火灾/爆炸：方案**缺灭火动作** → 已于第 3 位补入安全底线步骤

```

`_cap_steps` 先把方案截到 15，注入发生在其**之后** → 16 步；本条日志如实说明，**不静默超限**。

### ③ 验证：挡水假阳性 —— **通过**

`WARNING 挡水 … 不占位` 由 v8.19b 的 **1 处 → 0 处**（全 5 例）。
定点核对：`检查现场烟熏、积水和设备受损情况` → 挡水 flag **False**；`出入口积水倒灌站台` → **True**（真场景不漏）。
