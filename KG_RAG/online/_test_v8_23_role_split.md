## 一、交付：一个脚本、两种输入

```
# 模式 A：读已存的主方案 JSON（离线、确定性、可复算）
python tools/split_by_role.py --plan _v8_23_plan_1.json
python tools/split_by_role.py --plan plan.json --out ./lists      # 落成 4 个文件

# 模式 B：跑完整在线管道（同 main.py：解析→检索→生成），直接出 4 份清单
python tools/split_by_role.py --event "某地铁站台一名乘客突然晕倒，有意识但面色苍白。"
python tools/split_by_role.py --event "…" --dump-plan plan.json   # 顺带存 JSON
```

**如何拿到主方案 JSON —— 不改第 1 层**：`_capture_obj()` 在**运行期**把
`plan_generator._render_markdown` 换成包装函数，只记录它的 `obj` 入参再原样转调。
`plan_generator.py` **一字未改**。

**核心逻辑**（纯函数，可单测）：

```
split(obj) → (groups, unclassified, meta)
  1. 遍历 obj["steps"]，按 _role_category 分 4 组
  2. 遍历 obj["escalation"]["extra_steps"]，同法分组，标记 _upgraded=True
  3. 组内按**原 n** 升序（pg._n 数值排序）；**不重编**
  4. 类别取不到的 → unclassified（**如实报出，不静默丢弃**）
```

## 三、边界情况（逐条验证）

| 边界 | 处理 | 实测 |
|---|---|---|
| 某类**无步骤** | 输出「本事件该类岗位**暂无独立任务**」，**不空着** | ✅ 3 处（用例1 调度指挥；用例2 调度指挥+后勤安保）|
| 某步**并列双岗** | 两个岗位清单都出现（`岗位：站务员、车站员工`）| ✅ 用例 1 步骤1 |
| `n` **不连续** | 保留原值（`（n=2）`、`（n=7）`…），**不重编** | ✅ 全部 |
| **升级增补**步骤 | 标【升级后】；无 `n`/`action_type` 时不渲染空洞括注 | ✅ `**步骤6**【升级后】` |
| 类别**取不到** | 归入「未归类」段并标「须复核」，**不混入四类** | ✅ 离线用例已验（本次 3 例未触发）|
| 主方案**无步骤** | 输出「无可分派任务」（信息不足场景）| ✅ 离线用例已验 |

**步骤号显示**：`**步骤{本类序号}**（n={主方案步号}，{action_type}）` ——
本类序号便于岗位内部认领，`n` 用于与主方案 §二 对照（按任务书样例格式；`n` 保留原值）。

## 四、过程中发现并修复的一个真错（我方脚本）

**现象**：首轮 `--event` 模式跑出的方案，依据全是 `AIEP28 28C [步骤1]` 这类**兜底水淹章节**，且日志有
`AttributeError: 'NoneType' object has no attribute 'encode_queries'`（**每用例 2 处**）。

**根因**：`main.py` 的检索函数读的是**模块级全局** `bge_model` / `collection`
（在 main.py 里初始为 `None`，**只有其 `__main__` 段才赋值**）。我的驱动只调了 `load_encoder()` 的**返回值**、
**没写回全局** → **检索静默失败** → 方案在**没有规程上下文**的情况下生成。

**修复**：`run_event()` 改为 `app.bge_model = app.load_encoder()` / `app.collection = app.load_collection()`。
**修复后**：0 Traceback；依据恢复为真实章节（`AIEP03 3A3`、`AIEP01 1C5`、`GB/T 38707 14.2.15`、`AIEP12 12B3`）。

> 首轮输出**已作废**（`_test_v8_23_raw.txt` 为修复后重跑）。此处记录，因为它是个**容易重犯的坑**：
> 脱离 `main.py` 复用其检索时，**必须写回它的模块级全局**。

### 一处观察（**第 1 层既有行为，非本脚本问题**）

用例 1 出现**内容重复**：车站管理 步骤3（`n=8`）的动作含「…；填写事件记录并按规定上报相关部门」，
而**步骤5（`n=10`）本身就是**「填写事件记录并按规定上报相关部门」。
即 `_merge_steps` 把记录类步骤并进了 `n=8`，但 `n=10` 仍独立存在 → **分派清单里同岗位会看到两次**。
**属第 1 层合并的产物，本脚本不隐藏、也不去重**（去重会掩盖上游问题）。**供你判断**。
