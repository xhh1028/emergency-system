## 〇、缘起与**方案取舍**

需求方原本要求**整体替换**主 Prompt 为「8 阶段扁平 JSON 数组」模板。开工前核查发现该做法会**砸掉下游**：

- `_render_markdown`（250 行）读的是 `obj["event"]["severity"]` / `obj["steps"][].action_type`；
  扁平数组进来后 `obj.get("steps")` → `None`，直接命中「steps 为空」兜底或走
  `plan_generator.py` 的**「渲染失败（代码缺陷）」**路径。
- 连带失效的还有：`basis`→`_check_citations`（引用可证实性，v8.21 刚验证）、
  `action_type`→TIER/`_demand_slots`/`_order_steps`、`depends_on`→`_apply_depends`、
  `_insufficient_info` 拒绝生成门。v8.x 那套 20+ 轮回归也随之失去意义。
- 新模板的 8 阶段里，「分级响应」「信息上报」是**机制**不是时间阶段，
  与现有 `parallel_with`（并行声明）冲突——拉成顺序反而让时序更不合理。

**经用户确认，改走「增量补强」**：保留 dict schema 与渲染器，只嫁接有效部分；
8 阶段作为**覆盖清单**叠加在现有 4 阶段上（`stage` 仍四选一）。检索侧改动**独立且照做**。

## 二、图谱脏节点过滤：**判据是数据选出来的，不是拍的**

### 2.1 先确证 bug 真实存在

`offline/build_neo4j.py:39,47` —— `Action.name` **直接取自** `action_text`：

```python
action = record["action_text"]
MERGE (a:Action {name: $action})
```

而 `output/parsed_records.jsonl` 实录：

```json
{"record_id": "T982", "role": "公司范围、财物或员工受到的任何恐吓", "action_text": "一律视作", ...}
{"record_id": "T983", "role": "所有枪械", "action_text": "一律视作", ...}
```

→ **模态词被抽成动作**，且「角色」是一整句话。**用户判断属实。**

### 2.2 关键发现：**长度是坏判据**

按长度分档抽样 `action_text`（2646 条）：

| 长度档 | 抽样特征 |
|---|---|
| 8–12 字 | **反而更脏**：「应根据需要及时调整」「同样有可能受水淹影响」「依照本章14A2的程序」 |
| 12–16 字 | **才是真动作**：「使用无线电通知驾驶员立即停车」「关上门窗将火与空气隔绝」 |

长度分布：`p50=13, p90=33, max=75`。**用长度阈值会同时杀掉好动作、放过坏短句。**
真正区分「节点名 vs 规范性从句」的信号是：**规范性前缀** / **章节交叉引用** / **句子级标点**。

### 2.3 按节点类型**分级**（代价不对称）

- **Action 层从严** ← 用户报的 bug 就在这层；动作可**低成本丢弃**（prompt 里第一依据已是规程原文）
- **Role / Entity / Condition 层从宽** ← 岗位是**分派依据**，误杀代价大。
  实测严格模式会误杀「有关驾驶员」「相关管理人员」「车站督导员、公安人员」等**合法岗位**。

**实测保留率**（离线 2646 条 与 线上 Neo4j 真实库 双重核对，数字一致）：

| 层 | 保留率 | 说明 |
|---|---|---|
| Role（宽） | **98.0%**（537→526） | 被滤掉的 11 条全是「附录B：救援服务」这类真脏 |
| Action（严） | **33.7%**（1879→634） | 存活的都是真动作 |

**故意保住的**（长度不是判据）：`使用无线电通知驾驶员立即停车`、`操作站台两边的紧急停车按钮`、`维持未受影响的区间的列车服务`
**故意滤掉的**：`一律视作`、`应根据需要及时调整`、`依照本章14A2的程序`、`必须与车辆段控制中心及安保部协调，调派维修及保安人员：巡视所有轨道`

> ⚠️ **诚实记录**：顿号「、」**故意不在**句子标点集里——它多是**并列实体名**
> （「行车调度员、车辆段列车控制主管」）。代价是 `公司范围、财物或员工受到的任何恐吓`
> 这类含顿号的碎句在**宽模式**下会漏过；因它只作「补充参考」且不触发本 bug，暂不为此加规则。

### 3.4 「救治缺失」告警——**判定为随机抖动，非回归**

首轮 3 用例跑出 2 次 `全文无 救治 动作的第 1 档步骤 → 不占位`，基线 v8.22 是 1 次。**受控复跑**：

| 用例 | 复跑次数 | 救治告警 |
|---|---|---|
| 乘客晕倒（唯一真正需要救治的场景） | **3** | **0 / 0 / 0** |
| 垃圾桶起火 | 1 | 1 |
| 积水倒灌 | 1 | 0 |

→ 基线 3 用例合计 1 次、本版合计 1–2 次，**在 temperature=0.2 的 LLM 抖动范围内**（基线样本仅 n=1）。

> 该告警是 `_demand_slots` 的**软提示**（"不占位"，不丢内容）：指「救治动作没落在第 1 档首句」，
> 而非「方案没有救治内容」。且本版内容**更全**——起火用例基线 5 步且**无任何**救治/急救文字，
> 本版 14 步且含 `急救/救治` 内容。
