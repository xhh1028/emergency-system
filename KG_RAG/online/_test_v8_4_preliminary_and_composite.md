# v8.4 初判等级（双轨）+ 复合事件显式分析

## 一、要解决的问题（用户口述需求，转写整理）

1. 系统**只在给到精确数字时**才能定级；但初衷是**对不精确的自然语言描述做初判/预判**；
2. 初判之后，要能给出**可实施、可落实**的处置步骤，并能**借鉴库里的历史案例**；
3. 事件是**多场景融合**的，不能只讲一种险情；
4. 这是**接多模态之前**的过渡能力。

经确认走 **方案 A（双轨）** + **复合事件显式分析**。

**为什么不直接把 `level` 改成"推断"**（方案 B）：规程 7.2 四条判据**全是量化门槛**（死亡/重伤/经济损失/中断时长），
且既有 prompt 约束（一）明确"信息不足时必须原样写…、禁止按可能后果推断"——该约束的初衷正是**防止 LLM 编造等级**。
故**保留合规定级，另立初判字段**，两者并列、互不替代。

## 二、改动（3 处）

### 1. JSON schema

```json
"severity": {
  "level": "信息不足，暂按一般事件处置，持续跟踪升级",
  "preliminary": {"level": "特别重大|重大|较大|一般|无法初判", "confidence": "高|中|低",
                   "basis": "依据描述中实际出现的定性事实（不得引入未提及的数字）"},
  "tiers": [...], "conclusion": "..."
},
"impact": "...",
"composite": {"risks": ["险情1","险情2"], "interaction": "这些险情如何相互放大"}
```

### 2. prompt

- 约束（一）后追加 **（一·补）必须同时给出"初判等级"**：五选一 + 置信度 + 依据；**只许依据描述已出现的事实，不得引入未提及的数字**；与 `level` **各自如实填写、不得互相替代**。
- 新增 **（十三）复合事件必须显式拆解**：`composite.risks` 逐条列、`interaction` 说明如何相互放大；`steps` 仍是**一条**可执行主线。
- 标题 `以下十二条` → **`以下十三条`**。

### 3. 渲染（`_render_markdown`）

- 在「事故等级」下增 **`初判等级：X（置信：Y）`** + `依据：…`；
- 在「影响范围」下增 **`复合情形：本事件同时包含 N 类险情`** + 逐条 + `相互影响：…`；无则写"未识别为多险并发"。

**未触碰**：`KW_*` / `POSITION_RULES` / `COUNT_RULES` / `TIER` / `_flags` / 检索层 / 排序·合并·cap 逻辑（diff 核对为空）。

## 六、两点如实观察

1. **初判可能被描述里"既成结论词"带跑**：case_003 的依据里直接引了描述自带的"重大人员伤亡责任事件"——
   合规（确实是描述已出现的事实），但**等于抄了案例自己的定性**。若描述被人为标注过，初判会被带偏。
   后续若要多模态输入（原始描述），此风险自然消失；当前文本输入下值得留意。
2. **`composite` 由 LLM 生成，非代码推导**——它是"让模型说清多险并发"，**不保证穷尽**。
   与失败模式 5（置信提示缺失）相关：目前仍未告诉用户"这份险情清单可能不全"。
