## 六、⚠️ 一处必须报告的 spec / 验收不一致

**规则本身的要求满足了**（`最早 A` 早于 `最早 B`，9/9），但验收里那句"类别 B 步骤**都**在类别 A 步骤之后"**没有全部满足**——

因为 **A 类步骤不止一条**，而规则按你的规定"**只交换这一对**"：

- run 6：交换后 `A=[2,12]`、`B=[4,5,11,13]` → A12 仍在 B 之后；
- 回放场景 2：交换后 `A=[2,5,11]`、`B=[4]` → A5、A11 仍在 B 之后。

**成因**：A 类词表同时命中了**两类语义**——
① 真正的**隔离动作**（`隔离受影响区段的牵引电流`）——这才是"进区间前必须完成"的硬前置；
② **"已隔离"的通知类**（`轨道馈电断路器已打开` 的通知、`关断牵引电流后执行接地保护`）。

把 ② 也要求排在所有 B 之前，语义上是过严的。

**两个可选方向（等你裁定，本轮不改）**：
- **(a) 保持现规则**：安全底线（隔离动作本身先于进区间）已守住；如需更严，把 A 词表拆成"隔离动作"与"隔离通知"两档，只对前者要求早于 B。
- **(b) 循环交换**：反复交换"最早的违规 A 与最早 B"，直到全部 A 早于全部 B。仍是成对交换，但会移动更多步骤——**超出你"只交换这一对"的约束**，故未擅自实施。
