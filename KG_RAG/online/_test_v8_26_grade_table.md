## 〇、**一处照做会引入错误，已偏离**（需确认）

指令要求：「当前为 IV 级时：触发条件写 *若达到 XX → 升级为 III 级*」（即**逐级 +1**）。

**这条是错的，没有照做。** 理由：

> 当前 **IV 级**，触发条件是「死亡≥30 人」（**特别重大**事故）。
> 按"逐级 +1"会写成 **→ 升级为 III 级** —— 那**严重漏响应**，正确目标是 **Ⅰ 级**。

**正确语义**：目标级别由**阈值命中的事故档次**决定，即
**特别重大 → Ⅰ级；重大 → Ⅱ级；较大 → Ⅲ级；一般 → Ⅳ级**，可能一步跨多级。

指令后半段（**Ⅰ级 → "已达最高响应级别"**）是**对的**，已实现。

实测该偏离的确按预期工作（`_test_v8_26_fire_raw.txt`）：

```
- **当前响应级别**：III 级
- 若发生 死亡10人以上30人以下或重伤50人以上100人以下或… → 升级为 II 级（依据：7.2 重大事故）
- 若发生 死亡30人以上或重伤100人以上或直接经济损失1亿元以上 → 升级为 I 级（依据：7.2 特别重大事故）
```

### ★ 关键设计：**阈值列由代码渲染，不由模型重述**

约束（一）里本就记着教训 —— 模型曾编出「重大：6–24 小时」「较大：2–6 小时」这种
**整体错位的阈值**。阈值是**静态事实**，模型每重述一次就多一次漂移机会。
因此：**阈值列一律由 `_GRADE_TABLE` 渲染**，模型只负责填"本事件该指标的当前数值"
（`metrics[].value`）与该指标落在哪档（`metrics[].level`）。

配套容错：`metrics` 整块缺失 / 漏填某行 / 填了非法指标名 / `value` 写成 `无`、`—`、`N/A`、`null`
→ 一律归一为「未提供 / **待核实**」，**行不省略**。

### ★ 升级守卫（对应指令"升级逻辑无循环错误"）

`_esc_level_and_triggers()` 两条规则：
1. **目标级别必须严格高于当前** —— 同级或更低一律丢弃并告警（那不是"升级"，是**无操作**）。
2. **当前已是 Ⅰ 级** → 触发条件清空，渲染「**已达最高响应级别（Ⅰ级）**」，
   并给出正确表述「报请省级人民政府 / 国务院**提高应对层级**」。

## 三、端到端实测（地下深埋区间列车火灾）

**定级段**（指令要求的四点全部命中）：

```
- **精确判定**：**四项定级指标均缺失，无法对照国家标准进行精确分级**
- **保守初判等级**：**较大事故**（置信：中）
  - ⚠️ **此为保守推断，非国家标准量化判定** —— 依据的是对同类事件极端危险性的一般认识，
    **仅用于确定响应规模与处置力度，不得作为事故定级结论**
- **⚠️ 待核实项**：死亡人数、重伤人数、直接经济损失、连续中断行车

- **定级依据对照表**（口径：`X人以上Y人以下` = **含 X 不含 Y**）：
| 指标 | 当前数值 | 国家标准阈值（特别重大 / 重大 / 较大 / 一般） | 对应等级 |
|---|---|---|---|
| 死亡人数 | 未提供 | ≥30 人 / 10人以上30人以下 / 3人以上10人以下 / 3人以下 | **待核实** |
| 重伤人数 | 未提供 | ≥100 人 / 50人以上100人以下 / 10人以上50人以下 / 10人以下 | **待核实** |
| 直接经济损失 | 未提供 | ≥1 亿元 / 5000万元以上1亿元以下 / 1000万元以上5000万元以下 / 50万元以上1000万元以下 | **待核实** |
| 连续中断行车 | 未提供 | —（7.2 无此条） / 24小时以上 / 6小时以上24小时以下 / 2小时以上6小时以下 | **待核实** |
```

### ★ 升级守卫在**真实运行中抓到了一个真的循环**

`_test_v8_26_fire_raw.txt` 实跑日志：

```
WARNING [plan] [esc] 触发条件「死亡3人以上10人以下或重伤10人以上50人以下」目标 III
              不高于当前 III → 丢弃（非升级）
```

即：模型原本产出「**当前 III 级** ← 达到较大事故标准 → **升级为 III 级**」这个**无操作条目**
（因为保守初判已是"较大事故 → III 级"，"达到较大"自然不再构成升级）。
**没有这条守卫，它会原样渲染给读者**，正是指令担心的那类逻辑错误。

丢弃后剩余条目全部严格升级：

```
- **当前响应级别**：III 级
- 若发生 死亡10人以上30人以下或… → 升级为 **II 级**（依据：7.2 重大事故）
- 若发生 死亡30人以上或… → 升级为 **I 级**（依据：7.2 特别重大事故）
```

## 五、事故等级 → 响应级别：**1:1 硬映射**（v8.26 补充，经确认）

需求方确认后补上，定为**业务硬规则、硬编码**：

```python
GRADE_TO_RESPONSE = {"特别重大": "I", "重大": "II", "较大": "III", "一般": "IV"}
```

**为什么硬编码而不让模型填**：**响应级别决定"谁负责"**（省级还是市级），属**责任划分**，
不能由模型自由裁量。实现上：

1. `_grade_of(sev)` 取**当前生效**的事故等级 —— 精确判定成立用它，否则用**保守初判**。
   于是"已按保守初判定了事故等级"时，**同步写出建议的响应级别**（需求原文）。
2. 推导结果**覆盖**模型填的 `level` 与 `authority`；不一致时**告警留痕**（`[resp]`）。
3. **`_LVL_AUTHORITY`（4.1）绑定原样保留** —— Ⅰ/Ⅱ → 事发地省级人民政府；Ⅲ/Ⅳ → 事发地城市人民政府。
   由于响应级别现由等级推导，责任主体也随之**完全代码化**。
4. 简报与详案各输出一行「**级别推导**」，把推导链摆明（可审计）。

**实测**（`_test_v8_26_fire_final_raw.txt`，地下深埋区间列车火灾）：

```
- **响应级别建议**：III级 ｜ 责任主体：事发地城市人民政府 ｜ 报告时限：接报后30分钟内电话报告…
  - **级别推导**：事故等级「**较大**」（保守初判） → 响应级别 **III 级**（1:1 映射）；
    责任主体按 4.1 绑定 → **事发地城市人民政府**
```

**★ 顺带修掉一个子串陷阱**：`特别重大` 含子串 `重大`，
`_norm_grade` 若按字典序匹配会把「特别重大事故」误判成「重大」→ 响应级别从 Ⅰ 掉到 Ⅱ。
故按 `GRADE_ORDER`（长→短）**顺序**匹配，并加了专门断言。

**覆盖验证**：模型把 `response.level` 填成 `I`、`authority` 填成省级时，
代码按映射改回 **III 级 / 事发地城市人民政府**（断言：覆盖后**不再**出现"省级人民政府"）。
